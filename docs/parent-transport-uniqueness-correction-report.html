Parent–student uniqueness correction

The Development index representation was corrected without dropping, rebuilding or duplicating the existing index. Existing records and historical migration-ledger rows were preserved.

Production publication is still blocked. The regenerated publishing plan continues to drop the existing unique index and creates its replacement constraint after the dependent Transport foreign key.

Schema findings and source correction

  • Both inspected databases originally had the same sole standalone unique btree index, parent_student_relationship_unique, on (parent_id, student_id).
  • The relationship table has its primary key on id; parent/student identifiers are non-null integers with simple foreign keys. There was no pair UNIQUE constraint or second pair-unique index.
  • Development's transport_parent_requests_active_relationship_fk was already bound to that existing index.
  • The pair declaration in lib/db/src/schema/edupulse.ts was changed from uniqueIndex(...) to unique(...), retaining the exact same name and column order.
  • A guarded, repeatable correction is recorded in lib/db/drizzle/0037_parent_relationship_unique_constraint.sql. It attaches the existing index with UNIQUE USING INDEX; it does not rewrite historical migrations, create a second pair key, change application behavior or perform data backfills.

The observed defect is an index-versus-constraint/dependency representation and ordering problem in the publishing plan. Declaring the key explicitly exposes the replacement constraint, but does not make the current generated ordering safe.

Focused disposable rehearsal

A separate local PostgreSQL instance—not Development or Production—verified:

  • The constraint reuses the original index object.
  • The already-bound Transport foreign key retains its dependency.
  • Representative many-to-many relationship rows remain unchanged.
  • A duplicate parent/student pair is rejected with SQLSTATE 23505.

  • Repeating the guarded correction is a no-op, with one authoritative pair-unique index.

This is a focused correction rehearsal, not a successful rehearsal of the complete publishing plan. The disposable server was stopped afterward.
