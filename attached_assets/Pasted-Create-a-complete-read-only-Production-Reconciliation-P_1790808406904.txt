Create a complete, read-only Production Reconciliation Plan for Yemait EduCore.

IMPORTANT: THIS IS AN AUDIT/PLANNING TASK ONLY.

DO NOT:

- Publish or deploy anything.
- Execute the 408 pending schema statements.
- Run database migrations against Production.
- Modify Production.
- Create or alter Production tables, columns, indexes, constraints, functions, triggers, or data.
- Mark migrations as applied.
- Reset or replace the Production database.
- Copy Development into Production.
- Make manual Production fixes.
- Send real invitations.

The purpose is to determine exactly what must be done to safely bring Production into the required state before final publishing and live testing.

3. ANALYZE ALL 408 PENDING STATEMENTS

Reconstruct and categorize the current 408 pending schema synchronization statements.

For each category report:

- CREATE TABLE
- CREATE INDEX
- CREATE UNIQUE INDEX
- ALTER TABLE ADD COLUMN
- ALTER TABLE ADD FOREIGN KEY
- ALTER TABLE ADD UNIQUE CONSTRAINT
- any other statement

Confirm whether the current count is still exactly 408.

For each statement, determine:

- what object it affects
- whether that object already exists in Production

- whether another statement must execute first
- whether it could fail because of an existing Production object

- whether it could cause data compatibility problems

Do not execute the statements.

4. FOREIGN KEY DEPENDENCY ANALYSIS

This is critical.

Build a dependency map for ALL proposed foreign keys.

For every proposed FK verify:

1. referenced table exists or will be created first
2. referenced columns exist
3. referenced columns have an appropriate PRIMARY KEY or UNIQUE constraint
4. parent constraint exists before the FK is created
5. referenced data will satisfy the FK
6. child and parent column types match
7. tenant/school scoping is correct

Pay special attention to:

school_operation_categories

because previous analysis found proposed foreign keys referencing:

(id, school_id, category_type)

while the matching composite uniqueness requirement was not present in the 408 preview.

Determine exactly how this must be handled.

Also search for any OTHER foreign keys with similar missing-parent-key problems.
