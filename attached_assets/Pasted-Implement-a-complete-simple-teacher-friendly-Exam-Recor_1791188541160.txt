Implement a complete, simple, teacher-friendly Exam/Record and Result Management workflow for Yemait EduCore.

This is a targeted redesign of the existing result/academic-record workflow. Do NOT rebuild unrelated modules. First inspect the existing result, assessment, grading, report-card, teacher-assignment, academic-session/term, Student and Parent implementations and reuse working functionality where possible.

CORE PRINCIPLE

The workflow must be:

Teacher enters/submits results → Yemait EduCore calculates and compiles → School Admin reviews and publishes → Student and Parent see the published result on their dashboards.

School Admin must NOT be responsible for creating exams, CA, tests or assessment structures.

Teachers are responsible for entering the results of students they teach.

The system must make result entry extremely simple.

---

School Admin

Add/rename the School Admin dashboard section to:

Exam/Record

School Admin should use this section to:

- Select Academic Session
- Select Term
- Select Class
- Select Section
- View result submission status
- Open a class
- Preview individual student report cards
- Review complete consolidated results
- Publish results

School Admin must NOT create:

- Exams
- Continuous Assessments
- Tests
- Assignments for result entry
- Subject results
- Student scores

Teachers handle those responsibilities.

Platform Owner

Add:

Exam/Record

Platform Owner access must be strictly READ-ONLY.

Platform Owner workflow:

Exam/Record → Select School → Session → Term → Class → Section → Preview

Platform Owner may:

- View result submission status
- View submitted/unsubmitted subjects
- Preview student report cards
- View published/unpublished status
- Inspect consolidated class results

Platform Owner must NOT:

- Enter scores
- Edit scores
- Submit results
- Approve results
- Publish results
- Create exams
- Create CA/tests
- Change grades
- Modify report cards

Do not expose Platform Owner controls that can mutate result data.

2. TEACHER RESULT WORKFLOW

Make this the simplest possible workflow.

Teacher opens:

Teacher Dashboard → Exam/Record

The system should automatically know which classes and subjects the teacher is authorized to teach from the existing teacher/class/subject assignment records.

Do NOT make the teacher search through every school class and every subject.

Show something like:

My Results

Class| Subject| Term| Status| Action
SS2/B| Mathematics| First Term| Draft| Enter Result
SS1/A| Mathematics| First Term| Submitted| View
JSS3/A| Mathematics| First Term| Awaiting| Enter Result

The teacher clicks:

Enter Result

The system opens the result-entry table.

---

3. RESULT ENTRY TABLE

The teacher should see all students assigned to that teacher's authorized class/section/subject.

Example:

2026/2027 — First Term
SS2/B — Mathematics

Student| CA 1| CA 2| Exam| Total| Grade
Student A| | | | Auto| Auto
Student B| | | | Auto| Auto
Student C| | | | Auto| Auto

Make data entry extremely fast.

Support:

- Keyboard Tab navigation
- Enter/next-cell navigation
- Numeric-only score fields
- Score range validation
- Paste multiple cells from Excel
- Save Draft
- Continue later
- Submit when complete

The teacher should NOT manually calculate Total or Grade.

The system calculates them automatically using the school's existing grading configuration.

---

4. DO NOT FORCE TEACHERS TO CREATE EXAMS OR CA

Do NOT require this workflow:

Create Exam → Create Assessment → Add Questions → Assign Assessment → Open Results → Enter Scores.

That is unnecessarily complicated for this use case.

Instead, the teacher should simply enter the applicable result components.

For example:

CA 1 + CA 2 + Exam

or whatever assessment components are already configured for that school.

If the school uses a different grading structure, reuse the existing grading configuration.

Do not hard-code one grading scheme if the existing system already supports configurable grading.

---

5. EXCEL RESULT UPLOAD

Teachers must have:

Upload Excel

Provide:

Download Result Template

The template should contain the students already belonging to the selected class/section and subject.

Example:

Student ID/Admission No| Student Name| CA 1| CA 2| Exam
EDU001| Student A| | | 
EDU002| Student B| | | 

The teacher fills the Excel file and uploads it.

After upload:

NEVER immediately save the imported scores.

First display:

Import Preview

Show:

- Students matched
- Students not found
- Invalid scores
- Missing scores
- Duplicate rows
- Students outside the teacher's authorized class/section
- Any other validation problems

Example:

«42 students detected
40 valid
1 invalid score
1 student not found»

Allow the teacher to correct the file and retry.

Only after successful validation should the teacher click:

Import Results

Imported results become Draft.

The teacher can then review and:

Save Draft or Submit Result.

Do not allow an Excel upload to bypass authorization or tenant isolation.

---

6. PDF RESULT UPLOAD

Also provide:

Upload PDF

PDF import must be treated as an assisted import, not blind automatic data entry.

The system should:

1. Extract the tabular result where possible.
2. Match students using the safest available identity such as internal student ID or admission number.
3. Validate the extracted scores.
4. Show an import preview.
5. Clearly identify uncertain/unmatched rows.
6. Require teacher confirmation before saving.

NEVER silently guess a student's score.

If the PDF cannot be reliably interpreted, show a clear message and allow the teacher to use Excel or manual entry instead.

---

7. SUBJECT TEACHER RESTRICTIONS

A subject teacher must only enter results for:

- Their assigned school
- Their assigned class/section
- Their assigned subject
- The selected academic session
- The selected term

For example:

Mathematics Teacher → Mathematics only.

They must not be able to edit:

- English
- Biology
- Physics
- Chemistry
- Another teacher's class
- Another school's students

Reuse the existing teacher-class-subject assignment and tenant-isolation rules.

Do not weaken authorization to make result entry easier.

---

8. CLASS TEACHER RESPONSIBILITIES

The Class Teacher may have a class-level section for information that belongs to the class teacher rather than a subject teacher.

Where already supported by the system, this can include:

- General teacher comment
- Conduct/behaviour
- Attendance summary
- Affective/psychomotor ratings
- Class teacher recommendation
- Promotion recommendation

Do not make the Class Teacher responsible for entering another subject teacher's academic scores unless they are also explicitly assigned to that subject.

---

9. AUTOMATIC RESULT COMPILATION

This is critical.

Each subject teacher submits only their subject.

Example:

Mathematics Teacher → Mathematics submitted.

English Teacher → English submitted.

Biology Teacher → Biology submitted.

Physics Teacher → Physics submitted.

The system automatically combines the submitted subject results into the student's consolidated term record.

The identity of a subject result must remain scoped by:

School + Student + Academic Session + Term + Class/Section + Subject

Do not overwrite one subject when another teacher submits their subject.

Do not create separate overall results for each teacher.

13. PUBLISHING

School Admin should be the person who publishes the completed report.

Do not require School Admin to approve every individual subject separately.

Subject teachers submit their subjects.

The system compiles the complete report.

School Admin reviews the complete report card.

Then:

Publish Result

Before publishing, verify that required subject results are complete.

If something is missing, clearly show:

«Chemistry result has not been submitted by the assigned teacher.»

Do not allow an incomplete report to be accidentally published.

If the existing system supports an authorized administrative override, preserve that capability but make the warning explicit and audit the action.

Child A → Child A result

Child B → Child B result

- Session

- Subjects
- Scores
- Grades
- Average

16. RESULT STATUS MODEL

Use clear states:

Draft

Teacher is still entering/editing.

Submitted

Teacher has submitted the subject result.

Returned

School Admin returned it for correction.

Resubmitted

Teacher corrected and resubmitted it.

Ready for Review

All required subject results are available.

Published

School Admin has published the student's consolidated report.

Locked

Published result cannot be casually changed.

If a correction is required after publication, use the existing authorized reopen/return mechanism and maintain a complete audit trail.

20. SECURITY AND DATA INTEGRITY

Preserve strict tenant isolation.

A teacher from School A must never access School B results.

A Parent must only access linked children.

A Student must only access their own published result.

School Admin must only access their school.

Platform Owner can preview across schools only through the authorized school-selection workflow.

Do not use admission numbers as internal database IDs where APIs expect internal IDs.

Do not weaken existing authorization simply to make the UI work.
