4. PRODUCTION DATABASE MIGRATION AUDIT

There has previously been a production migration validation issue involving:

"nfc_card_history"

and a foreign key referencing:

"nfc_cards(id, school_id)"

The PostgreSQL requirement is that the referenced columns have an appropriate unique/primary constraint.

Investigate the current migration chain and determine exactly:

1. Which migration creates "nfc_cards".
2. Which migration creates or alters "nfc_card_history".
3. Which migration creates the composite uniqueness required for "(id, school_id)".
4. The order in which those migrations execute.
5. Whether the FK is being created before the required unique constraint.
6. Whether the problem exists only during publish-time validation or also in the development database.
7. Whether later migrations already address the issue.
8. Whether the migration chain is internally consistent.

IMPORTANT:

Do not automatically edit the migration.

First identify the exact root cause.

If a migration change is required:

- propose the smallest forward-only migration/change
- preserve all existing production data
- do not delete or recreate tables
- do not reset production
- do not alter unrelated migrations unnecessarily
- test the corrected migration on a disposable database/fork before production

If the issue is already resolved by later migrations, do not make another migration.

Determine whether the problem is:

Type A — Application routing bug

Type B — Clerk/provider configuration

The Clerk invitation or redirect configuration is incorrect.

Type C — Environment configuration

Type D — Expired/revoked/invalid invitation

The actual invitation ticket is invalid.

Type E — Already fixed
