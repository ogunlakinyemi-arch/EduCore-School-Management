Yemait EduCore — Consolidated Testing Feedback Correction & Enhancement

You are working on the existing Yemait EduCore school management platform under Yemait Technologies Limited.

This is a correction/enhancement pass based on accumulated testing feedback.

CRITICAL RULES

1. Do NOT rebuild the application from scratch.
2. Do NOT replace existing working modules unnecessarily.
3. Preserve all existing functionality, data, authentication, RBAC, Finance, NFC, Attendance, Academics, Partners, Invitations, Communications, Library, Operations, Reporting and dashboards.

6. Platform Owner must retain global visibility/control appropriate to the existing architecture.

8. Teachers, Staff, Parents, Students and Partners must only see information appropriate to their roles.
9. Reuse existing database models, APIs, payment infrastructure, NFC infrastructure and design system wherever possible.
10. Before changing the database, inspect the existing schema and migrations. Create only the migrations actually required.
11. Do not manually alter production data.
12. Do not run destructive SQL such as DROP/TRUNCATE/DELETE as part of this work.
13. Preserve existing production records.
14. All financial actions must have an audit trail.
15. All payment-related operations must be idempotent and protected against duplicate payments/transfers.
16. Do not expose secret keys, bank credentials or payment-provider secrets in frontend code or ordinary database fields.
17. Use secure server-side environment/secrets management for provider credentials.
18. Complete the work in Development first.
19. Run appropriate automated tests, typechecks and database/schema validation.
20. Do not publish to Production automatically.
21. At the end, provide a concise implementation and testing report and clearly state whether a database migration is required.
