PHASE 11C-A — HISTORICAL MIGRATION EVIDENCE COLLECTION

Objective

Investigate the historical reason migrations "0005–0030" are absent from the development migration ledger.

This is an evidence-collection task only.

ABSOLUTE RULES

DO NOT:

- modify the development database
- modify the migration ledger
- modify migration SQL
- create/drop/alter database objects
- mark migrations as applied
- execute reconciliation
- reset the database
- query production
- publish/deploy
- change application behavior

Use repository history, local files, Git metadata, logs, configuration history, and disposable copies only.

Inspect the complete Git history relevant to:

- migration files

- deployment/publish

---

2. MERGE HISTORY

Specifically investigate merge commits.

For every merge that touched migrations or database infrastructure:

- identify merge commit
- identify both parents
- identify migration files changed
- determine whether migrations were introduced before or after the merge
- determine whether the migration runner/ledger logic changed
- determine whether migrations could have been applied through another path

Pay special attention to periods where:

- migrations were rebased
- migrations were renamed
- migrations were squashed
- branches were merged
- database initialization changed
- migration numbering changed
- deployment configuration changed

Do not assume a merge caused the problem unless evidence supports it.

---

3. SEARCH FOR DATABASE LOGS

Search the repository and available local project artifacts for:

- migration logs
- application startup logs
- Replit deployment logs if locally available
- database initialization logs
- migration runner output
- SQL execution logs
- error logs
- backup logs
- restore logs
- development startup logs

Search for exact strings including:

"school_classes_id_school_tenant_key"

and migration filenames "0005" through "0030".

If logs are unavailable, explicitly state that.

Do not fabricate historical evidence.

---

4. SEARCH FOR MIGRATION LEDGER HISTORY

Find every occurrence of the migration ledger table name and migration insertion logic.

Determine:

- when the ledger was introduced
- whether its schema changed
- whether migrations were ever recorded differently
- whether ledger inserts occur before or after SQL execution
- whether failed migrations could leave schema changes without ledger rows
- whether migrations can be run outside the normal runner
- whether tests use a separate ledger
- whether development bootstrap bypasses the ledger

Inspect Git history for changes to this logic.

---

5. INVESTIGATE THE 0005 UNIQUE CONSTRAINT

The current failure is:

"0005" attempts to add:

"school_classes_id_school_tenant_key"

but the validated unique constraint already exists.

Investigate the earliest point in Git history where this constraint appears.

Determine:

1. Which migration originally introduced it.
2. Whether its definition changed.
3. Whether the current database definition matches the migration definition.
4. Whether an older migration version introduced it.
5. Whether application/bootstrap SQL introduced it.
6. Whether a manual setup script introduced it.
7. Whether a merge/rebase could explain its presence.

Do not alter the constraint.
