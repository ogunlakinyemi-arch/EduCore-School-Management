6. AUDIT RELATIONSHIP #1 — PLATFORM DEVICE → SCHOOL CLASS

If both required tables exist, audit:

platform_devices.school_id
platform_devices.school_class_id

Historical relationship:

(school_class_id, school_id)
→
school_classes(id, school_id)

Calculate:

A. Total platform_devices rows.

B. Rows with:

- school_id NULL
- school_class_id NULL
- both populated

C. Orphan class references:
school_class_id does not exist.

D. Cross-school mismatches:

platform_devices.school_id
<>
school_classes.school_id

when both values exist.

E. Historical composite compatibility:

Determine how many rows would satisfy:

(school_class_id, school_id)
→
school_classes(id, school_id)

and how many would violate it.

Do not validate or create the actual FK.

Report counts only.

allocation.attribution_id

school_partner_attributions.id

Calculate:

A. Total allocation rows.

B. attribution_id NULL.

C. attribution_id NOT NULL.

D. recipient_id NULL.

E. recipient_id NOT NULL.

F. Missing attribution references.

G. Attribution/recipient mismatches where recipient_id is NOT NULL.

H. NULL-recipient rows separately.
