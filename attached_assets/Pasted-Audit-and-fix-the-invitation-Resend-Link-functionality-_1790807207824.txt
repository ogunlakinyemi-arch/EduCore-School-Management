BUG TO FIX

Currently, when I click the “Resend Link” button for one pending invitation, the system appears to resend invitation links to all pending invitations instead of only the selected recipient.

The required behavior is:

«Clicking Resend Link on one pending invitation must resend ONLY that specific invitation.»

For example:

- Pending invitation A — Teacher
- Pending invitation B — Parent
- Pending invitation C — Student

If I click Resend on invitation B, ONLY invitation B should be resent.

A single resend action must never loop through or resend every pending invitation.

STEP 2 — VERIFY INVITATION IDENTITY

STEP 3 — BACKEND RESEND LOGIC

The backend resend endpoint/function must:

1. Receive the specific invitation ID.
2. Validate that invitation exists.
3. Validate that it is eligible for resend.
4. Validate that the authenticated user has permission to resend that invitation.
5. Load ONLY that invitation.
6. Preserve its:
   - recipient
   - role
   - school/tenant
   - partner context where applicable
   - expiration/security rules
   - authorization scope
7. Generate/send ONLY the replacement invitation for that record.
8. Update only that invitation's resend state/timestamp/status where applicable.
9. Return success for that single invitation.

There must be NO code path where a normal single-invitation resend automatically executes something equivalent to:

- select all pending invitations
- loop through all pending invitations
- resend all pending invitations
- Promise.all(allPendingInvitations.map(...))

unless that code belongs to a separately named and explicitly bulk-resend feature.
