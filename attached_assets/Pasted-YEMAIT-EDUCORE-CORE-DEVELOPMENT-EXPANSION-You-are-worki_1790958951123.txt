2. PUBLIC SCHOOL ADMISSION PORTAL

This is an important part of the admission system.

A school must NOT need to own or operate a website in order to receive online applications through EduCore.

Every school registered in EduCore should automatically receive its own public admission portal.

Public portal concept

The architecture should support:

Yemait Technologies
→ Yemait EduCore
→ School
→ Public Admission Portal

Each school gets a unique public admission URL based on its existing school identity/registration number or another safe unique identifier.

Example concept:

"EduCore Public Portal → Greenfield College → Apply for Admission"

Do not hard-code a specific production domain if the final domain has not yet been configured.

Use the existing application routing architecture so the final domain can be configured later.

- Admission number

- Current section
- Academic performance
- Attendance summary
- Recommended status
- Target class
- Target section

---

PROMOTION RESULTS

For promoted students:

- Preserve permanent Student ID.
- Preserve admission/registration number.
- Preserve NFC card.
- Preserve historical attendance.
- Preserve historical results.
- Preserve historical class/section records.
- Create new academic placement.
- Do not overwrite historical placement.

For repeat students:

- Preserve historical records.
- Create/retain appropriate new academic placement.

For graduated students:

- Preserve all history.
- Mark graduated.
- Do not delete student.
- Do not automatically revoke NFC identity.

For withdrawn/transferred students:

- Preserve historical records.
- Update lifecycle status appropriately.

---

CRITICAL NFC REQUIREMENT

Never tie the physical NFC card permanently to a student's current class.

The relationship remains:

NFC UID → NFC Card → Student → Current School Record

Example:

JSS1/A → JSS2/B → JSS3/A → SS1 → SS2 → SS3

The same physical NFC card continues to work.

Do not require reprinting simply because the student changes class, section or academic session.
