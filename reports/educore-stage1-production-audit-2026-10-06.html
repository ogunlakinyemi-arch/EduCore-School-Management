Standard chronological Drizzle migration behavior must not be used blindly here: old missing-ledger entries can be skipped below the latest timestamp, while newer non-idempotent DDL can collide with already-present schema objects. Physical state and ledger require separate reconciliation.

G. Production Configuration

lib/db/src/index.ts creates a pg Pool directly from DATABASE_URL; Drizzle uses the same variable in lib/db/drizzle.config.ts. There is no code-side environment-to-database selection or alternate fallback URL. Replit injects environment-specific runtime values, but a wrong configured DATABASE_URL would target the wrong database. The main push/push-force scripts have no target fingerprint guard. Several specialized Development scripts do have deployment/domain/key-prefix and/or exact database/start-time guards; those historical fingerprints are now stale and must not be bypassed.

scripts/post-merge.sh installs locked dependencies then runs pnpm --filter db push. This is schema push, not a replay of the 60 SQL files, and cannot establish function/trigger/backfill coverage or migration-ledger alignment. API startup runs subscription enforcement and communication workers, not migrations/DDL. Production artifact build runs the API build; runtime is Node with NODE_ENV=production and PORT=8080. No deploy-time migration hook was found in the inspected production entrypoint/artifact configuration.

Deployment metadata confirms a successful public autoscale deployment at the current platform-reported URL, but returns no database-resource binding or deployed Git revision.
