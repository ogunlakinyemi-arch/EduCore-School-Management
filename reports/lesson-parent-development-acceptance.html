Lesson Notes and Message Parent
Acceptance and preservation report

Existing authorized accounts and existing student/family data. Names, contacts, credentials and private storage URLs omitted.

23 of 25 live acceptance checks passed. Checks 18 and 23 are live-data blocked; native read-only query and UI regression coverage passed. The notification Open link was fixed and verified after refresh. Production was neither queried nor modified.

1. Exact root causes

  • Initially empty Student list: the client enabled the general student search only after more than one search character. Opening the dropdown with no search made no student-list request. The native dropdown itself worked. Searching returned student 721 and 730 from the general API; the old UI hid 730, so this is not evidence of an old visible unauthorized student option.
  • Lesson Notes authorized options: the teaching-context query required class-subject rows that were absent for valid staffing-only Teacher assignments. It therefore returned HTTP 200 with an empty array even though the timetable-authoritative assignments existed.
  • Communication permission: the existing Teacher lacked the separate Communication Send grant. Initial scoped reads consequently returned 404 “School security operation not found,” including the authorized student. Academic assignment is not this permission; the guard was not bypassed.

2. Exact fixes

  • Reuse the authoritative teaching eligibility scope for Lesson Notes; retain native selection controls and dependent Session → Term → Class/Section → Subject → Curriculum/Topic selection. Require confirmed applicable curriculum/topic context rather than guessing from PDF contents.
  • Load the communication-specific student endpoint immediately, with optional search. Resolve the signed-in account through its existing active Teacher employee record and current active student enrollments. Filter school, section, assignment, active/current session and student status on the server; include all qualifying assigned classes rather than all school students.
  • Load only existing authorized guardian relationships for the selected student. Use the existing thread, audit and notification lifecycle. The empty state is exactly “No linked parent/guardian is available for this student.”
  • Following explicit user approval, Admin 911 issued Development grant 4 to Teacher 912 in school 1393 through the existing authenticated grant endpoint. Its exact permission array is [COMMUNICATION_SEND]; audit 1601 records the School Admin actor. No other permission, teaching assignment or family relationship changed.
  • Add optional secure private PDFs, true PDF parsing, a 10 MB limit, authorized preview/download and immutable generation-pinned originals with SHA-256 hashes. Corrections create another document version; structured notes remain supported. Reuse Draft → Submitted → Returned → Resubmitted → Approved.
  • Keep existing weekly assignment uniqueness; duplicate new notes now return helpful 409 rather than 500. Do not mislabel that new-note conflict as an externally edited existing note.
  • Register the existing notification thread URL in authenticated Parent and school routing and reuse the existing authorized thread view. Stored notifications were not rewritten; server-side authorization remains intact.
